## Context

The core gem (`add-gem-core-signing`) exposes `Audioproxy.configure` / `Audioproxy.url_for` with no Rails awareness. Rails apps expect: configuration out of credentials, helpers in views, and zero boilerplate. The settled decision is a Railtie, not an engine — there is nothing to mount.

## Goals / Non-Goals

**Goals:**

- Railtie that wires config from Rails credentials with ENV fallback, and mixes helpers into ActionView.
- `audioproxy_url` and `audioproxy_audio_tag` helpers.
- The gem remains loadable and fully functional without Rails.

**Non-Goals:**

- ActiveStorage blob resolution (next slice).
- `blob.representation` transparency hook (explicitly out of scope for the MVP).
- Engine features: routes, views, migrations, generators.
- Preload-hint helper, `info`/peaks helpers (later, additive).

## Decisions

### D1: Build on the scaffolded railtie shell

The conditional railtie require, dev-only Rails dependency, and `Audioproxy::Rails` namespace all exist from `add-plugin-scaffold`; this slice only fills the railtie with initializer behavior and adds the helper mixin. Nothing in this slice touches the core namespace.

### D2: Configuration precedence — initializer > credentials > ENV

The Railtie applies configuration in an initializer that runs before app initializers would typically consume URLs, sourcing in ascending precedence: ENV (`AP_ENDPOINT`, `AP_KEY`, `AP_SALT`, `AP_ALLOW_INSECURE` for `unsigned` parity), then Rails credentials under the `audioproxy` key (`endpoint`, `key`, `salt`, `unsigned`), then anything the app sets explicitly via `Audioproxy.configure` in its own initializer (explicit wins because app initializers run after railtie initializers). Each attribute resolves independently — an app can keep key/salt in credentials and endpoint in ENV. Rationale for the ENV names: byte-for-byte parity with the proxy's own environment variables, so a dev docker-compose can share one env file.

### D3: Railtie only assigns what is present

Absent credentials/ENV assign nothing — no eager validation at boot. A production app with no key that generates a signed URL fails at `url_for` with the core's named configuration error (per `add-gem-core-signing`); a dev app running `unsigned` never needs a key. Alternative — validate at boot — rejected: it would break `assets:precompile`-style rake tasks and apps that only use unsigned/dev mode.

### D4: Helpers are a thin ActionView mixin

`ActiveSupport.on_load(:action_view) { include Audioproxy::Rails::Helpers }`. `audioproxy_url(source, **opts)` → `Audioproxy.url_for(source, **opts)`, nothing more. `audioproxy_audio_tag(source, **opts, html: {})` → `audio_tag(audioproxy_url(source, **opts), **html)` — the `html:` hash is the seam between proxy options and tag options, so option keys can never collide with HTML attribute names (`controls`, `preload`, `class`). Alternative — splat unrecognized keys into the tag — rejected: silently misrouting a typoed proxy option into an HTML attribute is exactly the confusion the explicit `html:` bucket prevents.

### D5: Test harness — the scaffold's dummy app plus view-level helper tests

The `test/dummy` app generated by `rails plugin new` (kept in the scaffold slice) exercises credential/ENV sourcing and helper availability at boot; helper rendering behavior is tested at `ActionView::TestCase` level. Credential-shape variations are driven by pointing the dummy app at test credential fixtures (or stubbing `Rails.application.credentials`) rather than spawning app processes.

## Risks / Trade-offs

- [Railtie initializer ordering vs. apps reading config at boot] → Config is applied in a `config.before_initialize`-adjacent railtie initializer; documented that URL generation belongs in request/job time, not class-load time.
- [`AP_ALLOW_INSECURE` mapping to `unsigned` may surprise] → It only sets the *client's* unsigned flag; the proxy independently enforces its own. Parity documented: set it in one shared env file for dev, never in production.
- [Credentials shapes vary (string vs symbol keys, nested vs flat)] → Read via `Rails.application.credentials.audioproxy` with indifferent access handling in one place; tested with both key styles.
